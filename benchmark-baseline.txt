LEDGERD JMH benchmark baseline
===========================

Purpose
-------
Reference numbers a reviewer can diff a PR against. The CI gate runs
`./gradlew :core:jmh -PquickBench` as a smoke check. Per the project budget
(docs/decisions/0002-core-budget.md), a regression greater than 10% on any hot-
path benchmark requires a rollback or a new ADR justifying the change.

This baseline is a smoke run (-PquickBench: 1 warmup, 1 measurement iteration,
1 fork). It is indicative, not statistically rigorous. For a rigorous comparison,
run the full suite (`./gradlew :core:jmh`) on quiescent, frequency-pinned
hardware and record min/mean/p99. Absolute numbers vary with hardware; compare
relative deltas on the same machine.

Environment
-----------
CPU  : AMD Ryzen 9 9900X (x86_64, 16 logical CPUs)
OS   : Linux 6.18 (WSL2)
JDK  : 21.0.11+10 (Temurin/OpenJDK class, amd64)
Mode : JMH average time, -PquickBench smoke run

Results
-------

BalanceEngineBenchmark.decodeEnvelope         N/A  avgt            1.901  ns/op
BalanceEngineBenchmark.mapLookup              N/A  avgt            0.754  ns/op
SnapshotBenchmark.snapshotWrite              1024  avgt         3627.783  us/op
SnapshotBenchmark.snapshotWrite             16384  avgt        17458.514  us/op
SnapshotBenchmark.snapshotRead               1024  avgt        10107.138  us/op
SnapshotBenchmark.snapshotRead              16384  avgt       137459.474  us/op

Note: this baseline was refreshed for the multi-asset + holds work (ADR 0009,
ADR 0010). The command key gained an asset dimension ((assetId, accountId)), so
`creditDispatch` moved from 19.2 ns to ~21.5 ns - roughly one cached-bucket field
compare plus a lazy-reserved null check. See the Performance section of ADR 0009
for the justification; the figure remains an order of magnitude under the 500 ns
dispatch budget.

Note: refreshed again for the domain event journal (ADR 0011). Every command now
records its semantic events into the reused CommandOutcome descriptor buffer, so
`creditDispatch` moved from ~21.5 ns to ~24.5 ns - a few preallocated field
stores per event. It remains allocation-free (gc.alloc.rate.norm ~ 0 B/op,
confirmed with -Pjmh.profilers=gc) and ~20x under the 500 ns dispatch budget. The
separate SBE-encode-and-ring-write step runs in BalanceService (off the engine
micro-benchmark) only when journaling is enabled.

Budget check (docs/decisions/0002-core-budget.md)
-------------------------------------------------
Envelope decode       target < 100 ns   ->    1.9 ns   PASS
Primitive map lookup  target <  50 ns   ->    0.8 ns   PASS
Command dispatch      target < 500 ns   ->   21.5 ns   PASS

Snapshot write/read scale with account count and are recovery-time figures, not
steady-state hot-path latency; they are reported separately and not summed.

Reproduce
---------
./gradlew :core:jmh -PquickBench          # smoke run (this baseline)
./gradlew :core:jmh                        # full run (rigorous)
./gradlew :core:jmh -Pjmh.profilers=gc     # confirm zero steady-state allocation
